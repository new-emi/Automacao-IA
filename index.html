📬 Automação de E-mails Diários

Pipeline 100% em nuvem que dispara e-mails personalizados para uma clínica internacional de saúde mental — eliminando tarefas repetitivas e liberando tempo da equipe para o atendimento clínico.

✅ Concluído ⏰ 09:00 America/New_York ☁️ 100% nuvem 💸 Custo zero 🎓 PUCPR · IA

Visão geral

O sistema lê diariamente uma planilha Google com mensagens programadas por data, filtra a do dia atual, monta um e-mail HTML personalizado para cada destinatário e envia via SMTP do Google Workspace — tudo rodando na nuvem, sem computador ligado.

  • O que faz: dispara um e-mail personalizado todo dia às 09:00 ET para a lista de contatos da clínica.
  • Para quem: pacientes, líderes comunitários e assistentes sociais em formação atendidos pela clínica.
  • O que entrega: e-mail HTML com saudação personalizada, mensagem do dia e imagem embutida.

Contexto, problema e solução

Problema A clínica mantinha a rotina manual de enviar diariamente um e-mail com reflexão e imagem para sua lista de contatos. A tarefa consumia tempo operacional e dependia da disponibilidade de uma pessoa específica.
Solução Automatizar o ciclo em 4 etapas: agendamento (cron-job.org às 09:00 ET com DST automático) → orquestração (GitHub Actions liga servidor e injeta credenciais via Secrets) → processamento (Python filtra a mensagem do dia) → entrega (SMTP do Workspace com pausa anti-sobrecarga).

Diagrama do pipeline

cron-job.org (09:00 America/New_York)
        │ POST na API do GitHub (workflow_dispatch + PAT fine-grained)
        ▼
GitHub Actions (ubuntu-latest, Python 3.12)
        │ injeta Secrets (GMAIL_USER, GMAIL_APP_PASS, CREDENTIALS_JSON)
        ▼
enviar.py ── lê a planilha via service account (gspread)
        │ filtra mensagem do dia no fuso da Flórida
        │ monta HTML personalizado por destinatário
        ▼
Gmail SMTP Workspace
        │ pausa de 1s entre envios
        ▼
Clientes — "Hello {nome} - {mensagem}" + imagem

Decisões técnicas justificadas

DecisãoJustificativa
n8n → GitHub ActionsFim do período gratuito do n8n levou a uma solução autônoma, gerando economia e mais segurança dos dados (crítico em saúde mental).
cron-job.org em vez do cron nativo do GitHubGatilho schedule mostrou instabilidade em repos novos; cron-job.org oferece timezone nativo e DST automático.
Fuso via zoneinfoZoneInfo("America/New_York") imuniza o código a mudanças sazonais sem cálculos manuais.
Credenciais em SecretsNenhum segredo no código — placeholders + injeção em tempo de execução.
PAT fine-grainedEscopo mínimo (Actions R/W em 1 repo) em vez de PAT clássico global.
Dia sem mensagem = silêncioEvita e-mails vazios; comportamento intencional.
Pausa de 1s entre enviosEvita sobrecarga do SMTP e risco de bloqueio por volume.

Segurança

  • Repositório de produção privado; este é o repo público de demonstração.
  • Segredos apenas em GitHub Secrets e no cron-job.org (header do job).
  • PAT fine-grained com escopo mínimo.
  • Service account com acesso de leitura apenas à planilha.
  • App password em vez da senha real da conta.
  • Credenciais locais existem apenas para testes manuais e nunca são commitadas.
